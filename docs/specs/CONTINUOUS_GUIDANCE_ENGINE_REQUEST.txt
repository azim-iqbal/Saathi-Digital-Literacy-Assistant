# SAATHI — FINAL CONTINUOUS GUIDANCE ENGINE AND PRE-DEPLOYMENT COMPLETION

You have access to Saathi's entire repository, previous remediation work, Git history, architecture and test evidence.

The app already has research, task planning, accessibility observation, field highlighting, local-first guidance, AI provider integration, privacy masking, pause/resume, sensitive-field handoffs and browser navigation.

Your task is to improve the existing architecture into a reliable, continuously reactive digital guidance assistant.

**Do not rebuild the entire codebase unnecessarily. Refactor only the components that require changes, preserve all accepted functionality, and maintain the existing UI.**

## Primary product requirement

Saathi must guide users through forms and digital workflows without requiring them to zoom in, zoom out, rotate the screen or manually trigger an accessibility refresh.

It must:

1. Discover visible form fields.
2. Identify their purpose.
3. Determine whether each is required, optional or unknown.
4. Detect when the user fills, clears or changes a field.
5. Determine whether the field is locally valid, invalid or unverified.
6. Highlight the appropriate next field.
7. Advance automatically when there is sufficient evidence.
8. Preserve the original task across navigation.
9. Handle private fields without interrupting the overall task.
10. Continue until the workflow reaches a verifiable completion state.

Keep every tap, submission, payment, declaration and authentication action under the user's control.

## Required behavior

When a user starts typing:

- Observe the relevant safe structural change.
- Keep the current field highlighted if it is incomplete.
- Do not dispatch an AI request for every keystroke.

When the user finishes:

- Evaluate available local validation evidence.
- Advance only if the completion criteria are satisfied.

When the user clears a field:

- Mark the previous completion evidence stale.
- Reassess dependencies.
- Return guidance to the field when necessary.

When an error appears:

- Identify the error using safe UI evidence.
- Explain what needs correction.
- Highlight the appropriate field.

When an optional field is empty:

- Allow the user to skip it.
- Do not block the workflow.

When requiredness is unknown:

- Do not silently classify it as required.
- Explain the uncertainty and provide an appropriate user-controlled continuation.

When the user navigates backward:

- Reconstruct current field states from fresh observations.
- Do not assume previous entries remain valid.

# PHASE 4 — AUTOMATIC NEXT-FIELD GUIDANCE

Create a deterministic next-field selection policy.

Prioritize:

1. Current invalid required field.
2. Current incomplete required field.
3. Next unmet conditional requirement.
4. Optional fields according to user preference or workflow relevance.
5. Next navigation control after form readiness is established.

Do not blindly select the first visible input.

Respect:

- Form order
- Dependency relationships
- Accessibility semantics
- User-visible validation
- Current focus
- Hidden fields
- Disabled fields
- Dynamic forms
- Multi-step forms

The user should not have to manually request the next highlight after every field.

However, Saathi must not automatically click buttons, submit forms or enter values.

# PHASE 5 — CONTINUOUS PRIVATE-FIELD GUIDANCE

Preserve privacy enforcement.

Do not disable NodeMasker.

Do not send passwords, OTPs, PINs, CVVs, authentication tokens or other secrets to the backend or AI providers.

Instead, allow the guidance session to continue through a privacy-preserving local handoff.

## Behavior

When Saathi reaches a sensitive field:

- Keep the original task active.
- Identify the field's purpose using safe structural metadata.
- Highlight the field if safe.
- Explain that the user should enter the information themselves.
- Suspend cloud processing of the sensitive screen.
- Disable listening during sensitive entry.
- Avoid reading or retaining the actual value.
- Use safe local progress indicators where available.
- Reobserve after the sensitive interaction.
- Continue automatically when a trustworthy safe transition is established.

Do not treat focus loss or a non-empty field as proof of successful authentication.

If the user remains on a protected screen, continue waiting.

If the user reports completion, verify the next safe screen before advancing.

## Non-sensitive content

For ordinary non-sensitive fields, support optional AI-assisted interpretation of field values only when:

- The user has been clearly informed.
- Explicit consent is obtained.
- The data is necessary for the requested guidance.
- Data minimization is applied.
- Existing backend privacy controls are respected.

No deceptive privacy messaging is permitted.
