# PHASE 2 — SEAMLESS SENSITIVE-FIELD HANDOFF

## Problem

Saathi currently pauses or enters a sensitive handover when encountering private fields.

This is safe but may interrupt the user's experience unnecessarily.

We want:

**Continuous task guidance without continuous access to sensitive data.**

The task remains active at the logical level, but sensitive observation and cloud processing remain suspended.

Do not remove existing privacy protections.

## 2.1 Introduce a user-controlled handoff state

Implement or extend the existing interruption state machine.

Conceptually support:

GUIDING
→ WAITING_FOR_PRIVATE_USER_ACTION
→ VERIFYING_SAFE_CONTINUATION
→ GUIDING

Preserve existing CAPTCHA and manual Pause states.

Do not collapse manual Pause, authentication handoff, CAPTCHA and payment uncertainty into one state.

The handoff must preserve:

- Original goal
- Current task plan
- Safe prerequisite state
- Current non-sensitive step
- Language
- Speech preferences
- Session identity
- Relevant non-sensitive context

Do not retain sensitive values.

## 2.2 Sensitive-field instructions

When Saathi detects a sensitive field, provide a short explanation in the user's selected language.

English example:

"This step needs private information. Enter it yourself. Saathi won't send it to AI or save it."

Hindi and Hinglish must communicate the same meaning naturally.

Avoid saying:

"I cannot see your OTP."

unless the implementation proves the value is never accessed by any Saathi component.

Prefer guarantees about what Saathi does not transmit, retain or process.

## 2.3 Safe field highlighting

Where Android provides a safe, trustworthy accessibility target:

- Highlight the sensitive field using structure-only metadata.
- Do not read its value.
- Do not include its contents in snapshots.
- Do not send its value to the backend.
- Do not send it to Gemini or Groq.
- Do not log it.
- Do not persist it.
- Do not speak it.

Do not use screenshots to bypass value masking.

If highlighting would require capturing sensitive content, withhold the highlight and provide text-only guidance.

If the accessibility target is ambiguous or unavailable, do not guess.

## 2.4 Completion detection

Use safe signals in priority order:

1. Verified transition to a non-sensitive screen.
2. Safe structural state change that indicates the sensitive step has ended.
3. Explicit user confirmation through an existing-style control.

A field becoming non-empty, losing focus, or the user tapping Next is not proof that authentication succeeded.

If a non-empty boolean is available without reading the actual value, it may be used only as a local progress hint.

Do not use it as an authentication-success predicate.

Avoid reading `AccessibilityNodeInfo.text` for sensitive values merely to compute whether a field is non-empty.

Use non-content structural indicators where available.

Do not cache or transmit even a sensitive-field completion hint unnecessarily.

## 2.5 Resume safely

After the sensitive interaction:

- Obtain a fresh screen observation.
- Verify the sensitive state has ended.
- Revalidate session identity.
- Revalidate task context.
- Reject stale AI responses.
- Remove outdated overlays.
- Continue with the next safe step.

If the screen remains private or protected, keep waiting.

If authentication failed, explain the visible failure safely without extracting credentials.

If the user cancels, preserve appropriate manual control.

If permissions are revoked or the screen locks, retain existing safety-stop behavior.

## 2.6 Voice privacy

Do not silently restart the microphone.

Prevent speech recognition from capturing spoken passwords, OTPs, PINs or other authentication secrets during handoff.

TTS may announce the safe handoff instruction if appropriate, but listening must remain disabled during sensitive entry.

Resume voice only according to the existing explicit consent and activation rules.

## 2.7 CAPTCHA

Preserve the existing CAPTCHA interruption mechanism.

Never solve, bypass or automate CAPTCHA.

Explain that the user must complete it.

Resume only after a fresh safe observation.
