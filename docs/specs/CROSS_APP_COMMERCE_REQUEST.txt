# PART 3 — WHAT SHOULD ACTUALLY BE PRIVATE

Use strong signals for sensitive fields.

Examples include:

### Authentication

- Password
- Passcode
- OTP
- TOTP
- Authentication code
- Login PIN
- MPIN

### Payments

- Card number
- CVV/CVC
- ATM PIN
- UPI PIN
- Net-banking password
- Payment OTP
- Security code
- Card expiry when entered as part of payment credentials
- Bank authentication secrets

### High-confidence secret/account fields

- Recovery code
- Security answer where clearly authentication-related
- Private authentication token
- Explicit credential fields

Potentially identifying information should follow the project's existing privacy/data-minimization policy, but do NOT blindly treat every name, address, phone-like label or number on a screen as authentication-secret data.

Do not turn an entire screen private merely because one private input exists.
